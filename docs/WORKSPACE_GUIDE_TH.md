# Project Workspace — คู่มือใช้งานและลำดับอ่านโค้ด

อัปเดต 17 ตุลาคม 2026 · ใช้หนึ่ง Workspace ต่อเรื่อง เพิ่มวิดีโอแต่ละตอนได้
เก็บข้อมูลในเครื่องด้วย SQLite ไม่ต้องมีเซิร์ฟเวอร์ และไม่ต้องโหลดภาพตัวละครภายนอก
ยังเป็นเครื่องมือ AI ช่วยจัดกลุ่ม/ตรวจแก้ ไม่ใช่ตัวระบุผู้พูดที่ยืนยันความแม่นยำแล้ว

## เปิดใช้ทันที

รันจาก root โปรเจกต์; เครื่องนี้มี dependencies และ weights แล้ว ไม่ต้องติดตั้งซ้ำ:

```bash
venv/bin/python -m src.main data/output/workspace-demo
```

ตัวอย่างนี้สแกน Test_1.mp4 ครบแล้ว มีภาพตัวอย่าง กลุ่มเสียง และซับ 23 แถว
ชื่อ/การรวมกลุ่มที่คุณตรวจไว้ยังอยู่ตามเดิม ระบบไม่ตั้งชื่อหรือยืนยันเพิ่มแทนคุณ
หากต้องการทดลองโดยรักษาผลเดิม ให้ปิดโปรแกรมแล้วสำเนาโฟลเดอร์ Workspace ทั้งชุด
เปิด Home ด้วย `venv/bin/python -m src.main`; `src.workspace_app` เปิดหน้าหลักเดียวกัน

## สามหน้า แหล่งข้อมูลเดียว

UI ใช้ PyQt6 และสลับจากแท็บด้านบน ไม่แสดงเครื่องมือทุกอย่างพร้อมกัน:

| หน้า | งานหลัก |
|---|---|
| Home | รายการโปรเจกต์ เลือก/สร้าง/เปิด/เปลี่ยนชื่อ/เอาออก/ย้ายไปถังขยะ |
| Subtitle Editor | วิดีโอ ซับปัจจุบัน waveform ตารางและแบบฟอร์มแก้บท/เวลา |
| Character Manager | แท็บย่อย **Dashboard** / **ภาพตัวละคร** / **เสียงผู้พูด**; ตรวจกลุ่มและยืนยันคู่ภาพ–เสียง |

**File / Edit / Analysis** อยู่มุมขวาบนของหน้าต่าง ไม่ซ้ำแถวปุ่มสร้าง/เปิดด้านล่าง
ไอคอนมีคำอธิบายเมื่อวางเมาส์; คลิกขวาหรือ secondary click บนรายการ/ตารางเพื่อดูคำสั่งรอง
Home ไม่โหลดวิดีโอหรือเตรียม waveform จนกว่าจะเข้าหน้าแก้ซับ
ตัวเล่นใน Manager แยกจาก Editor: ฟังหลักฐานแล้วกลับมา ตำแหน่งและ draft ใน Editor ไม่ถูกแทนที่
เสียงของหน้าที่ซ่อนจะหยุดชั่วคราว ไม่เล่นสองหน้าทับกัน

### Home และการจัดการไฟล์

File → **สร้างโปรเจกต์** ถามชื่อ โฟลเดอร์แม่ วิดีโอ และ SRT (สองไฟล์ท้ายเว้นแล้วเพิ่มภายหลังได้)
สร้างในโฟลเดอร์ใหม่/ว่างเท่านั้น ไม่เขียนทับโปรเจกต์เดิม; SRT ต้องมีวิดีโอที่ใช้คู่กัน
File → **เปิดโปรเจกต์** เลือกโฟลเดอร์ที่มี `workspace.sqlite3`; ดับเบิลคลิกใน Home เข้า Editor
เปลี่ยนชื่อโปรเจกต์เปลี่ยนชื่อแสดง ไม่ย้ายโฟลเดอร์

คลิกขวาโปรเจกต์มีสองคำสั่งแยกกัน ทั้งคู่ถามยืนยัน:

- **เอาออกจาก Home (เก็บไฟล์ไว้)** ลบแค่รายการ เปิดกลับได้จาก File
- **ย้ายโฟลเดอร์โปรเจกต์ไปถังขยะ** ย้ายทั้งโฟลเดอร์ รวมไฟล์ใดที่เก็บอยู่ด้านใน; กู้คืนจากถังขยะของระบบได้ วิดีโอที่อยู่นอกโฟลเดอร์ไม่ถูกแตะ และไม่มีการลบถาวรทดแทนเมื่อย้ายไม่สำเร็จ

รายการ Home อยู่ใน `data/output/studio-library.json` ไม่ใช่ฐานข้อมูลตัวละคร ไม่สแกนทั้งดิสก์หาโปรเจกต์

### หน้าแก้ซับ

เลือกบรรทัดเพื่อแก้ข้อความ ชื่อในบท และเวลาเข้า/ออก (`HH:MM:SS,mmm`)
กดไอคอนบันทึก, ⌘/Ctrl+Enter หรือ File → **บันทึกบรรทัดที่กำลังแก้** (⌘/Ctrl+S)
ข้อความที่ยังไม่บันทึกเป็น draft; เปลี่ยนบรรทัด/ตอน/โปรเจกต์หรือปิดจะถาม Save / Discard / Cancel
สลับไป Manager อย่างเดียวไม่ทิ้ง draft และเปลี่ยนชื่อโปรไฟล์แล้ว draft ยังอยู่

เล่น/หยุดใช้ ⌘/Ctrl+Space; waveform คลิกเลื่อนเวลาได้ และแสดงเสียงต้นฉบับรวมเพลง/FX ไม่ใช่เสียงคนที่สกัดแล้ว
“ตามวิดีโอ” เลื่อนตารางตามช่วงที่เล่น โดยไม่เปลี่ยนบรรทัดที่กำลังแก้
คลิกขวาตารางเพื่อเพิ่ม/ลบ/แยก/รวมบรรทัด กำหนดตัวละคร ล้างชื่อแก้มือ หรือไปดูหลักฐาน
แยกบรรทัดใช้ทั้งตำแหน่งวิดีโอและเคอร์เซอร์ข้อความ; รวมต้องเป็นบรรทัดติดกันและไม่ขัดกับชื่อที่ยืนยันไว้
ค้นหาบทพูด/ผู้พูดได้; ส่งออกจาก File เป็น SRT เฉพาะบท, SRT พร้อมชื่อ หรือ JSON
ยังไม่เทียบเท่าฟีเจอร์ทั้งหมดของ Subtitle Edit และยังไม่รองรับ ASS/VTT หรือ redo

### เล่น MKV ผ่านไฟล์ cache

File → **การเล่นวิดีโอ** → **ใช้โหมดเล่นลื่นสำหรับ MKV** เปิดไว้ตอนเริ่มโปรแกรม
เมื่อเข้า Editor หรือเปิดหลักฐาน MKV ครั้งแรก จะเตรียมไฟล์ MOV สำหรับ playback ใน worker
คัดลอก video stream เมื่อรองรับ และแปลง audio ทุกแทร็กเป็น stereo PCM 48 kHz; codec วิดีโออื่นอาจต้อง encode
ไม่เอาซับฝัง/font attachment ลง preview เพราะ UI แสดงซับจาก Workspace อยู่แล้ว

ต้นฉบับไม่เปลี่ยน: การสแกน AI, waveform, fingerprint และ export ยังอ้างข้อมูลเดิม
cache อยู่ที่ `<workspace>/cache/playback/`; ใช้พื้นที่วิดีโอเพิ่มหนึ่งชุด + PCM ประมาณ 11.5 MB/นาที/แทร็ก
ตัวอย่าง MKV 23 นาที 40 วินาทีในเครื่องนี้มี preview ประมาณ 1.6 GiB
ไฟล์วิดีโอที่แปลง codec อาจต้องการพื้นที่มากกว่าค่าประมาณ; หากเตรียมไม่สำเร็จยังกลับไปเล่นต้นฉบับได้

ระหว่างเตรียมจะพัก playback และล็อกงานเขียนอื่น; draft ไม่ถูกทิ้ง กดหยุดยกเลิกได้
หลังสำเร็จทั้ง Editor และ Manager ใช้ cache โดยรักษาตำแหน่งเล่นแยกกัน
ปิดโหมดนี้เพื่อกลับต้นฉบับ; **เตรียมไฟล์เล่นลื่น / ลองใหม่…** ใช้ลองใหม่หลังหยุดหรือผิดพลาด
ไม่วนลองเองซ้ำเมื่อผิดพลาด/ยกเลิกใน session เดียว และไฟล์ที่ยังไม่พร้อมไม่ถูกเลือกมาเล่น
การลาก seek bar เปลี่ยนเวลาตอนปล่อยเมาส์ เพื่อลดการสะดุดจาก seek ถี่ ๆ

โหมดนี้ผ่านการทดสอบ decoder/เวลา/draft แต่ยังไม่รับรองอาการเสียงที่ได้ยินทุกกรณี
ถ้ายังกระตุก แจ้งช่วงเวลาและอุปกรณ์เสียงที่ใช้ ดู [ข้อจำกัด MKV](KNOWN_ISSUES_TH.md)

### เปิดงานจากหน้าจอเดิม

ใช้ `venv/bin/python -m src.main --legacy-reference` แล้วกด **Project workspace**
เลือกสร้างหรือเปิด Workspace เพื่อส่งวิดีโอ ซับ และชื่อแก้มือเข้าฐานเดียวกันโดย worker
ถ้าขัดกับข้อมูลที่มีอยู่จะปฏิเสธ ไม่ทับเงียบ ๆ และไม่ยืนยันชื่อ AI เป็นคำตอบคน
หลังนำเข้าให้ทำงานต่อในหน้าหลักใหม่; ไม่ใช่ live sync ระหว่างหน้าต่างเก่ากับใหม่
ยังไม่ได้สร้างปลั๊กอิน Subtitle Edit และยังไม่ทำหน้ากระดาษ Word/ส่งออก PDF ตามขอบเขตที่ตกลงไว้

## วิธีทำงานกับเรื่องใหม่

1. File → **สร้างโปรเจกต์** — เลือกโฟลเดอร์แม่และตั้งชื่อเรื่อง โปรแกรมสร้างโฟลเดอร์ใหม่/ว่างเท่านั้น
2. File → **นำเข้าวิดีโอ** — เพิ่มแต่ละตอน ตรวจ SHA256 ป้องกันการเพิ่มไฟล์เนื้อหาเดียวกันซ้ำ ไม่แก้หรือสำเนาวิดีโอต้นฉบับ
3. ไป Character Manager → **สแกน** หรือเมนู Analysis; ตั้งค่า `auto` และ **สกัดเสียงคนก่อนวิเคราะห์** ใน Analysis → ตั้งค่าการสแกน
4. รอผลแล้วเลือกแท็บภาพ/เสียงและกลุ่มทางซ้าย กลุ่มภาพมี thumbnail; ดับเบิลคลิกช่วงเพื่อดูวิดีโอ หรือคลิกขวา → **ฟังไฟล์เสียงวิเคราะห์**
5. **เปลี่ยนชื่อทั้งระบบ** — เปลี่ยนชื่อของ profile ID เดิม ทุกตอน/ซับที่อ้าง ID นั้นแสดงชื่อใหม่ทันที ไม่รัน AI ใหม่
6. ถ้ารวมผิด เลือกช่วงที่ผิดแล้ว **แยกช่วงที่เลือกเป็นกลุ่มใหม่** หรือ **ย้ายช่วงที่เลือก**; ถ้าแยกมากเกินไปใช้ **รวมเข้ากลุ่มอื่น**
7. **ยืนยันกลุ่ม** ล็อก membership ปัจจุบันไม่ให้ AI เปลี่ยนทับ ช่วงใหม่ที่เพิ่มในอนาคตยังเป็นข้อเสนอและต้องตรวจเพิ่ม
8. ไป **Dashboard** เลือกคู่เสนอ → **ดู / ฟังหลักฐาน** → กลับ Dashboard → **ยืนยันคู่เสียง–ตัวละคร** หรือเลือกตัวละครเองหลังตรวจ โปรแกรมไม่ถือว่าคนที่อยู่ในจอเป็นคนพูดโดยอัตโนมัติ
9. File → **นำเข้าซับ SRT** หรือ Analysis → **สร้างช่วงซับจากเสียง (ไม่มีข้อความ)** หากยังไม่มีซับ ข้อความว่างไม่ได้ถูกถอดเสียงให้อัตโนมัติ
10. ใน Subtitle Editor คลิกขวาซับ → **กำหนดตัวละคร** เพื่อให้อ้าง profile ID และเปลี่ยนชื่อตามทั้งระบบ หรือพิมพ์คอลัมน์สุดท้ายเพื่อแก้เฉพาะแถว
11. File → **ส่งออก** JSON เพื่อเก็บหลักฐาน/ผลตรวจ หรือ SRT โปรแกรมให้ใช้ชื่อไฟล์ใหม่ ไม่ทับต้นฉบับ

คำสั่งในข้อ 5–8 มีในเมนูคลิกขวาที่กลุ่มหรือช่วงหลักฐานด้วย
การจัดกลุ่ม/ชื่อ/ลิงก์/ชื่อเฉพาะแถวบันทึกทันที ส่วนข้อความและเวลาในแบบฟอร์มซับต้องกดบันทึกบรรทัด
Edit → **ย้อนการแก้ล่าสุด** ย้อน rename, merge, split/move, link, label, import, สี/ชุดสี และการแก้ cue ได้
ชื่อโปรเจกต์/รายการ Home และการย้ายถังขยะไม่อยู่ใน undo ของซับ/ตัวละคร
เพิ่มโปรไฟล์จากไอคอน +; ลบโปรไฟล์ด้วยคลิกขวา เก็บหลักฐานไว้ในกลุ่มยังไม่จัด และเก็บชื่อที่ยืนยันในซับเป็นข้อความ ย้อนคืนได้
การกำหนดชื่อหลายแถวเป็นหลายรายการ undo ตามจำนวนแถว ไม่มี redo ในรุ่นนี้
เลือกหลายแถวด้วย Shift/Cmd กลุ่มว่างจากรอบเก่าถูกซ่อนไว้ เปิดดูได้ด้วย checkbox ด้านซ้าย
กลุ่มและคู่เสนอใน Dashboard ใช้หลักฐานทั้งเรื่อง ส่วนจุดซับใช้ตอนที่เลือกในช่องวิดีโอ
คำแนะนำในรายละเอียดแท็บเสียงใช้ตอนที่เลือก; ไม่เอาเวลาจากคนละตอนมาเทียบกัน

## คู่เสียง–ภาพและ Dashboard

สำหรับโปรเจกต์เก่าที่มีผลสแกนแล้ว ให้กด **ตรวจคู่ภาพ–เสียง** ใน Dashboard หนึ่งครั้งต่อตอน
ใช้กรอบใบหน้าเดิมอ่านภาพที่ 8 fps เพื่อวัดปากเฉพาะ track ที่ทับเสียง ไม่รัน YOLO/CCIP ใหม่
ไม่เปลี่ยน profile ID, membership, ชื่อ, คู่ที่ยืนยัน, ซับ หรือประวัติแก้มือ; รอบถัดไปใช้ cache เมื่อข้อมูลตรงกัน
โปรเจกต์ใหม่ที่สแกนภาพและเสียงจะทำขั้นตอนนี้ต่อให้อัตโนมัติ แต่ยังไม่ยืนยันคู่แทนคน

ระบบเปรียบเทียบการเปลี่ยนแปลงบริเวณปากกับส่วนควบคุมของใบหน้า ชดเชยการเลื่อนและความสว่าง
ใช้เฉพาะคู่เฟรมที่ทับ speech turn แล้วรวมหลักฐานหลายช่วง ตรวจผู้สมัครสูสีและเสียงซ้อน
การเห็นหน้าเฉย ๆ ไม่เพียงพอจะเสนอว่าเป็นผู้พูด; ไม่มีภาพปาก/พูดนอกจอ/หลักฐานน้อย อาจไม่มีคู่เสนอ
ถ้าซับ SRT ระบุชื่อหน้าบท (`อควา: ...`) หรือผู้ใช้กำหนดชื่อ/กลุ่มภาพให้บรรทัดนั้นเอง
ระบบเทียบเวลาซับกับกลุ่มเสียงที่ทับเพียงกลุ่มเดียว และจับชื่อกับกลุ่มภาพที่มีชื่อเดียวกันแบบไม่กำกวม
ซับที่มีบทพูดแต่ไม่มีชื่อให้หลักฐานเวลาเล็กน้อยเฉพาะคู่ที่มีหลักฐานปากอยู่แล้ว ไม่ใช้สร้างชื่อใหม่
ช่วงซับว่างที่สร้างจากเสียงเองไม่ถือเป็นหลักฐานอิสระให้เพิ่มคะแนนซ้ำ
หลักฐานนี้ช่วยจัดอันดับคู่ที่มีภาพปาก หรือสร้าง **คู่เสนอจากซับเท่านั้น** เมื่อยังไม่มีภาพปาก
Dashboard บอกที่มาชัดเจน; ซับไม่มีชื่อไม่ใช้เดาตัวละคร เสียงซ้อน/เวลาคลาด/ชื่อขัดกันจะงดใช้ซับ
การเสนอจากซับไม่สร้าง link ถาวร ไม่ยืนยันว่าปากขยับ และยังต้องดู/ฟังก่อนกดยืนยัน
คะแนน **0–100** และระดับต่ำ/ปานกลาง/สูงเป็น heuristic ไม่ใช่เปอร์เซ็นต์โอกาสถูกต้อง
ส่วนภาพ/เสียงใช้โมเดล AI ที่มีอยู่ แต่ส่วนจับคู่ปาก–เสียงนี้ **ยังไม่ใช่โมเดล lip-sync ที่ฝึกมาโดยเฉพาะ**

เลือกแถวคู่เสนอแล้วกด **ดู / ฟังหลักฐาน** เพื่อเปิดวิดีโอต้นฉบับในแท็บเสียง จากนั้นกลับ Dashboard เพื่อยืนยัน
ปุ่ม **เลือกตัวละครเอง…** ใช้เมื่อข้อเสนอผิดหรือไม่มีคู่; ทุกการผูกมีหน้าถามยืนยัน
เสียงหนึ่งกลุ่มผูกได้หนึ่งตัวละคร แต่หลายกลุ่มเสียง เช่นเสียงปกติ/เสียงใส่ FX ผูกกับตัวละครเดียวกันได้
การเปลี่ยนปลายทางจะถามแทนคู่เดิม; รวมกลุ่มเสียงที่ผูกคนละตัวละครไม่ได้จนกว่าจะแก้คู่ให้ตรงกัน
ข้อมูลเก่าที่มีหลายปลายทางไม่ถูกเปลี่ยนเงียบ ๆ ให้เลือกปลายทางที่ถูกต้องใหม่

หลังผูก ชื่อและสีเสียง resolve ผ่านตัวละครเดียวกันทุกตอนและในซับ ไม่สำเนาชื่อแยกจนแก้ไม่ตาม
เปลี่ยนชื่อจากแท็บเสียงที่ผูกแล้วก็เปลี่ยนตัวละครร่วมกัน ส่วนชื่อกลุ่มเสียงเดิมเก็บเป็นข้อมูลประกอบใน tooltip
ซับที่กำหนดด้วย profile ID ตามชื่อใหม่ด้วย; ชื่อที่พิมพ์เป็นข้อความเฉพาะแถวไม่ถูก AI เขียนทับ
การผูกตัวตนไม่ใช่การรับรองว่า membership ของทุกช่วงเสียงถูกทั้งหมด ต้องตรวจ/แยกกลุ่มที่ปนกันก่อน

### กราฟเครือข่ายสไตล์ Obsidian และสี

- จุดเล็กคือบรรทัดซับจริงของตอนที่เลือก จุดใหญ่คือกลุ่ม; เมื่อผูกแล้วภาพกับเสียงใช้กลุ่มและสีเดียวกัน
- เส้นทึบคือ membership; เส้นประเชื่อมเพื่อนบ้านจาก cosine similarity ของเสียงในโมเดลเดียวกัน สูงกว่าเกณฑ์ที่ตั้งไว้ (เริ่ม 0.65)
- ใช้เพื่อนบ้านใกล้สุด 3 ต่อบทแล้วรวมเส้นซ้ำ ไม่เทียบเวกเตอร์เสียงกับภาพหรือข้ามโมเดล และไม่สร้างเส้นความคล้ายให้บทที่ไม่มีเวกเตอร์/พูดซ้อน
- ตำแหน่งใช้แรงดึง–ผลักบน XY โดยใช้ PCA เป็นค่าเริ่มต้น **ไม่ใช่แกนสถิติหรือระยะ embedding ที่อ่านเป็นคะแนนได้**; similarity ไม่ใช่ความมั่นใจผู้พูด
- ลากจุด: จุดข้างเคียงขยับตามแรง แล้วจุดที่ลากจะถูกตรึงไว้; คลิกขวา → ปล่อยจุด หรือกดปุ่มคืนตำแหน่ง การลากไม่ย้ายสมาชิก/ผูกชื่อ
- ลากพื้นหลังเลื่อนกราฟ หมุนล้อซูม วางเมาส์บนจุดเพื่อเน้นเพื่อนบ้าน คลิกดูบท ดับเบิลคลิกเปิดซับ/กลุ่ม คลิกขวาเปลี่ยนสี
- ค้นหาชื่อหรือข้อความเพื่อเน้นจุด; เลือกจุดแล้วติ๊ก **รอบจุดที่เลือก** เพื่อแสดงเพื่อนบ้านชั้นเดียว
- ไอคอนตั้งค่ามีแรงดึง/แรงผลัก/แรงรวมศูนย์ เกณฑ์เส้นความคล้าย หยุดเคลื่อนไหว และแสดงกลุ่มที่ไม่มีบทในตอนนี้
- ปุ่ม Home จัดให้พอดี, +/− ซูม, Enter เปิดจุดที่เลือก, Esc ยกเลิกการเลือก เมื่อกราฟมี focus
- จำกัดตัวอย่าง **500 บท** กระจายตั้งแต่ต้นถึงท้ายตอน พร้อมจุดกลุ่มที่เกี่ยวข้อง; ไม่ลดผลวิเคราะห์หรือลบซับจริง
- แสดงจำนวนบทที่วาด/ทั้งหมดชัดเจน กลุ่มที่ยังไม่ทราบไม่ถูกจับยัดเป็นตัวละครเดียว; เส้นและจุดไม่ใช่ผลยืนยันความถูกต้อง
- การเคลื่อนไหวหยุดเองเมื่อนิ่ง/ครบช่วงเวลาคำนวณ และหยุดทันทีเมื่อซ่อนหน้า; ตำแหน่งลากเก็บระหว่างใช้งาน ไม่บันทึกลงฐานหรือคงไว้ข้ามการเปิดโปรแกรม
- ปุ่มชุดสีมุมขวาของ Dashboard มี Studio / Pastel / Contrast; แก้สีในชุดหรือเพิ่ม Custom ได้รวม 64 สี
- กลุ่มใหม่รับสีอัตโนมัติจากชุดที่เลือกและวนใช้เมื่อครบชุด; สีไม่ใช้เป็นหลักฐานตัดสิน AI
- ค่าเริ่มต้นเปลี่ยนชุดสำหรับกลุ่มใหม่เท่านั้น ถ้าเลือกใช้กับกลุ่มเดิมด้วยจะแทนสี Custom เดิมและย้อนคืนได้

## ภาพกับเสียงแยกกันอย่างไร

สแกน **ภาพและเสียง** รอบใหม่ทำเสียงก่อน เพื่อใช้ช่วงพูดกรองงานภาพ (เผื่อหัวท้าย 250 ms)
ช่วงไม่มีเสียงจึงไม่ส่งเฟรมเข้า YOLO/CCIP; คนฟังที่อยู่พร้อมคนพูดยังอาจเป็น visual observation ได้
สิ่งนี้ไม่เท่ากับการยืนยันว่าเป็นผู้พูด การจับคู่ต้องผ่านหลักฐานปากกับเสียงและการตรวจของคนอีกขั้น
ถ้าสแกนเฉพาะภาพโดยยังไม่มีผลเสียง จะตรวจภาพตามเวลาเช่นเดิม; รอบเก่าที่มี cache ไม่ถูกบังคับสแกนใหม่

ภาพ: อ่านวิดีโอตามลำดับเวลา เลือกประมาณ 4 เฟรม/วินาที ย่อกว้างไม่เกิน 640 พิกเซล
ใช้ YOLO หาใบหน้า, track ภายในหน้าต่าง 8 วินาที แล้วเลือกไม่เกิน 3 crop ต่อ track ให้ CCIP สร้างเวกเตอร์ลักษณะตัวละคร
เทียบ metric ของ CCIP กับตัวแทนกลุ่มเดิม ถ้าคล้ายให้เป็นสมาชิก ถ้าแตกต่างสร้างกลุ่มใหม่ ถ้าสูสีเว้นไว้ตรวจ
track คนละตัวที่อยู่พร้อมกันไม่รวมอัตโนมัติ กลุ่มข้ามตอนใช้ model fingerprint เดียวกัน
นี่เป็น sampled coverage: คนที่ปรากฏสั้นมาก/หน้าเล็กอาจพลาด ไม่ได้ตรวจทุกเฟรม

ภาพที่บันทึกเพิ่มใหม่เป็นรูปตัวแทนไม่เกิน **4 รูปต่อกลุ่มทั้งโปรเจกต์** และไม่เกิน 32 รูปสำหรับภาพยังไม่จัดกลุ่ม
ย่อด้านยาวไม่เกิน 256 px, JPEG quality 80; ยังเก็บ embedding, เวลาและกรอบของทุก observation เพื่อย้อนดูวิดีโอ
รูปเดิมไม่ถูกลบ จึงอาจมีมากกว่าเพดานในโปรเจกต์เก่า; ไม่จำเป็นต้องมี JPEG ทุกช่วงเพื่อยืนยันคู่เสียง–ภาพ

เสียง: FFmpeg เตรียม stereo 44.1 kHz จากต้นฉบับ → Kim Vocal 2 (MDX) สกัดเฉพาะ Vocal
→ mono 16 kHz → pyannote segmentation ผ่าน sherpa-onnx → WeSpeaker embedding → กลุ่มเสียงของทั้งเรื่อง
ไม่มีไฟล์แยก instrumental/drums/bass/Foley และไม่ได้ทำ sound-event classification
Vocal อาจมีเสียงร้องเพลงหรือเสียงรบกวนหลงเหลือ ไม่ใช่การรับรองว่าเป็นบทสนทนาล้วน

เสียงกับภาพใช้คนละ profile ID จนกว่าผู้ใช้เชื่อม ความเป็นนักพากย์คนเดียวกันไม่ได้แปลว่าเป็นตัวละครเดียวกันเสมอ
มีคำแนะนำจากเวลาและการขยับปาก แต่ไม่สร้าง link ถาวรเอง; ข้อมูลเก่าที่มีหลายปลายทางจะไม่สุ่มเลือกชื่อหนึ่งคน
เสียงนอกจอยังจัดเป็นกลุ่มผู้พูดได้ ส่วนไม่มีเสียงก็ไม่มีหลักฐานเสียงให้ระบุคนพูด
ช่วงพูดซ้อนหรือสั้นกว่า 1 วินาทีไม่ใช้สร้าง identity ใหม่อัตโนมัติ แต่ยังเก็บช่วงไว้ให้ตรวจ

## อ่านผลและคะแนน

- `proposed` / `PROPOSED`: ข้อเสนอ AI ยังไม่ใช่ผลยืนยัน
- `ambiguous` / `AMBIGUOUS`: หลักฐานสูสีหรือมีเสียงที่ยังจัดกลุ่มไม่ได้; export เป็น UNKNOWN เมื่อยังมีส่วนไม่แน่ใจ
- `pending`: ยังไม่จัดกลุ่ม เช่นตัวอย่างน้อย/ช่วงเสียงสั้น
- `confirmed`: membership ที่ผู้ใช้ยืนยัน ย้าย หรือรวมด้วยมือ
- `MANUAL`: ซับมีคำตอบแก้มือ; `MULTIPLE_SPEAKERS`: ซับหนึ่งแถวทับหลายกลุ่มเสียง

ความคล้ายที่แสดงมาจาก 1 − distance ที่ clip อยู่ใน 0–1 ไม่ใช่เปอร์เซ็นต์ความถูกต้อง และห้ามเทียบข้ามโมเดลภาพ/เสียงตรง ๆ
confidence ของผลซับเป็น 0 พร้อมหมายเหตุว่าไม่ได้ calibrated; ไม่ควรใช้เป็น accuracy
ไม่มีการเดาเพศจากเสียง และยังไม่มีคำบรรยายทุ้ม/ใสหรือการรู้จำอารมณ์ในรุ่นนี้

## Cache, หยุด/ทำต่อ และความปลอดภัยของการตรวจแก้

**หยุด** หยุดงานของโปรแกรมนี้เท่านั้น ไม่ฆ่า process อื่น ผลหน้าต่างที่สำเร็จถูกบันทึกไว้
กดสแกนชนิดเดิม/ค่าตั้งเดิมเพื่อทำต่อ ภาพ checkpoint ทุก 8 วินาที; diarization ทุก 120 วินาที
Vocal checkpoint ทีละ 30 วินาทีพร้อมบริบทหัวท้าย 1 วินาที ช่วงที่เสร็จใช้ซ้ำได้ หลังต่อกันต้องยาวเท่าต้นฉบับ
ถ้าปิดระหว่างคำนวณ จะทำซ้ำเฉพาะหน่วยย่อยที่ยังไม่จบ ไม่สร้างผล complete ปลอม

SQLite เก็บ IDs, embeddings, membership, links, subtitles, manual edits, undo history และตำแหน่ง resume
เก็บชุดสี/สีแต่ละกลุ่มใน metadata และ mouth activity ตามเวลาใน evidence; การวิเคราะห์ปากหยุด/ทำต่อทีละหน้าต่างได้
`evidence/` เก็บ thumbnail ที่ใช้อ้างอิง ส่วน `cache/` เก็บ WAV/chunk/งานคำนวณซึ่งสร้างใหม่ได้จากต้นฉบับและโมเดลเดิม
ไฟล์ตัวอย่างเสียงหายแล้วกดสแกนเสียงเดิม ระบบสร้าง cache ใหม่โดยไม่เขียนทับการจัดกลุ่มที่ตรวจแล้ว
อย่าลบ `workspace.sqlite3` หรือ `evidence/` หากต้องการเก็บงาน; หยุด/ปิดโปรแกรมก่อนจัดการ cache เอง

key ของการสแกนผูกกับ SHA256 เนื้อหาวิดีโอ โมเดล และค่าตั้ง ไม่ผูกแค่ชื่อไฟล์
ถ้าแก้ไฟล์วิดีโอต้นทางจะไม่เอา cache เก่ามาใช้ ให้เพิ่มเวอร์ชันใหม่เป็นอีกตอน
หากเปลี่ยนโมเดล/ค่าตั้งหลังล็อก membership ระบบจะปฏิเสธการทับรอบเดิม ให้ใช้ค่าตั้งเดิมหรือ Workspace ใหม่
ยังไม่มี migration แบบเปลี่ยนโมเดลแล้วโยงผลตรวจเก่ากับ track ใหม่อัตโนมัติ
กรณีไม่มี membership ที่ล็อก สามารถสแกนค่าตั้งใหม่ได้; กลุ่ม/ชื่อเก่ายังอยู่แต่หลักฐานรอบเก่าไม่ถูกใช้เสนอผลปัจจุบัน
จึงควรยืนยันกลุ่มที่ตรวจแล้วก่อนทดลองเปลี่ยนค่าตั้ง

หนึ่ง Workspace อนุญาตงานเขียนหนึ่งตัวในเวลาเดียวกัน ป้องกัน CLI/GUI สองชุดแก้ขณะแสกนกันเอง
undo ไม่ลบหลักฐานใหม่ที่สแกนเพิ่มภายหลัง การเริ่มสแกนใหม่ไม่ล้างคำตอบแก้มือ
ยังไม่ได้ทดสอบไฟล์ฐานข้อมูลบน network filesystem; ใช้ดิสก์ภายในเครื่องก่อน

## JSON กับการย้ายทั้ง Workspace ไม่ใช่สิ่งเดียวกัน

JSON ส่งออกเป็น schema เดียวกับโปรแกรมเดิม มีเวลา ข้อความ ผล AI หลักฐาน และคำตอบแก้มือ
**นำเข้า JSON ที่ตรวจแล้ว** รับซับและคำตอบแก้มือ ไม่เอาข้อเสนอ AI ที่บันทึกไว้มายืนยันเป็นคำตอบของคน
Workspace เดิมรักษา manual profile ID; Workspace อื่นนำชื่อแก้มือเข้าเป็นข้อความ ไม่สร้างตัวตนใหม่จากชื่ออย่างเดียว
ถ้าวิดีโอไม่ตรงตาม hash หรือขัดกับคำตอบแก้มือที่มีอยู่ จะปฏิเสธโดยไม่ทับงานเดิม
SRT/JSON ไม่ได้บรรจุภาพ, embeddings, กลุ่ม, undo history หรือเสียงทั้งหมด จึงไม่ใช่ backup ทั้งเรื่อง

ย้ายเครื่อง: ปิดทุกหน้าต่างและ CLI ที่ใช้งาน Workspace แล้วสำเนา **ทั้งโฟลเดอร์** รวม SQLite/evidence/cache
นำวิดีโอต้นฉบับไปด้วย แล้วใช้ **เชื่อมไฟล์ที่ย้าย** ซึ่งตรวจ hash ว่าเป็นไฟล์เดิม
นำ models พร้อม metadata ไปด้วย/ติดตั้งตามแหล่งเดิม ไม่คัดลอก venv ข้ามระบบปฏิบัติการ
ไม่มีการอัปโหลดสื่อหรือ sync ฐานข้อมูลขึ้น cloud ในรุ่นนี้ การส่งงานอัตโนมัติไปเครื่องใหญ่ยังไม่รวม แต่เครื่องใหญ่อ่าน Workspace เดียวกันผ่าน CLI ได้

## ประสิทธิภาพบน Mac และเครื่องอื่น

Mac: `auto` เลือก MPS สำหรับ YOLO เมื่อมี; CCIP และ speaker models ใช้ CPU จำกัด 2 threads ต่อ session
Vocal แยก child process ใช้ตัวเลือกอุปกรณ์ของ audio-separator (MPS/CoreML บน Mac เมื่อรองรับ); เลือก cpu จะปิด GPU ในงานนั้น
เครื่อง CUDA ใช้ `--device cuda` กับ YOLO ได้ แต่ยังไม่ได้ทดสอบ CUDA/Windows จริงในงานนี้
ไม่รันภาพและเสียงหนักพร้อมกันใน worker เดียว จำกัดภาพหนึ่งหน้าต่างและเสียงหนึ่ง chunk ใน RAM
จำนวน embeddings/ประวัติเพิ่มตามข้อมูลจริง ไม่ใช่ใช้ RAM คงที่ตลอดทั้งโปรเจกต์; ยังไม่มี benchmark หลายสิบตอน

cache เสียงแบบไม่บีบอัดใช้พื้นที่หลายสิบ MB ต่อนาทีเมื่อรวมต้นฉบับสำหรับโมเดล, Vocal, mono และ chunk
Mac M4/16 GB เครื่องนี้รันตัวอย่างได้ ไม่จำเป็นต้องย้ายเครื่องเพื่อทดลองคลิปนี้ แต่ผลนี้ไม่ได้รับรองเวลา/หน่วยความจำของทุกเรื่อง

## ติดตั้งบนเครื่องใหม่เท่านั้น

เตรียม Python ที่มี wheel รองรับ versions ในไฟล์ requirements และ FFmpeg แล้วใช้ venv ของโปรเจกต์:

```bash
venv/bin/python -m pip install -r requirements.txt -r requirements-ai.txt
venv/bin/python -m scripts.setup_workspace_models
venv/bin/python -m scripts.setup_workspace_models --verify-only
```

setup ดาวน์โหลดเฉพาะโมเดล/metadata ที่เปิดเผยโดยผู้เผยแพร่ ไม่ส่งสื่อผู้ใช้
Mac ที่ใช้ Qt รุ่นได้รับผลกระทบต้องมี Command Line Tools สำหรับสร้าง guard ครั้งแรก ดู [Accessibility fix](MAC_ACCESSIBILITY_FIX.md)
anime-face YOLO เดิมให้เตรียมตาม [models README](../data/models/README.md) แยกจากสคริปต์นี้
`--verify-only` ตรวจ checksum แบบ offline; หากไฟล์ถูกเปลี่ยน สคริปต์ไม่เขียนทับเงียบ ๆ
การวิเคราะห์ไม่ดาวน์โหลดโมเดลเอง; ต้องมี model และ metadata ให้ครบก่อน
ตรวจเงื่อนไขการใช้งานของแต่ละโมเดลก่อนเผยแพร่หรือใช้เชิงพาณิชย์ ไม่อนุมานจาก license ของ wrapper

## CLI และลำดับอ่านโค้ด

สร้าง Workspace และสแกนทั้งคลิป:

```bash
venv/bin/python -m src.workspace_cli data/output/my-series \
  --create --video /absolute/path/episode01.mp4 \
  --subtitles /absolute/path/episode01.srt --scan all --device auto
```

ตอนถัดไปใช้คำสั่งเดิม **โดยไม่ใส่ `--create`** และเปลี่ยนวิดีโอ/ซับ
สแกนต่อใช้ `--video` ไฟล์เดิม หรือ `--media-id` ที่ CLI แสดง; Ctrl+C เก็บ checkpoint ที่เสร็จไว้
`--scan visual` / `voice` เลือกอย่างเดียว, `--no-separation` ทดลองเสียงต้นฉบับ, `--fps` เปลี่ยน sampling ภาพ
`--scan av` เพิ่มหลักฐานปาก–เสียงให้ track ที่มีอยู่ (ต้องมีผลภาพและเสียงก่อน) ไม่จัดกลุ่ม/ตั้งชื่อใหม่
`--import-review /path/review.json` นำคำตอบกลับ; `--export /path/new.json` หรือ `.srt` ส่งออก
การเปลี่ยน `--fps` / `--no-separation` เปลี่ยน cache key และติดข้อจำกัดผลตรวจแก้ข้างต้น

| อ่านตามลำดับ | รับอะไร → คืน/บันทึกอะไร |
|---|---|
| `workspace/store.py` | โฟลเดอร์ → Store; เก็บ ID, transaction, profile, review, undo |
| `pipeline/workspace_scan.py` | Store + media ID + ScanSettings → run key; บันทึก track/ภาพ/เวกเตอร์ |
| `vision/character_embedding.py` | list ของ crop BGR → matrix embeddings; query + references → distances |
| `workspace/clustering.py` | Store + kind + distance function → จัด membership (ไม่คืนค่าผลใหญ่) |
| `audio/vocal_worker.py` | stereo WAV + model → Vocal WAV/chunks; ทำงานใน process แยก |
| `audio/speaker_features.py` | mono NumPy array → list ช่วงผู้พูด/เวกเตอร์/overlap |
| `pipeline/workspace_audio.py` | Store + media ID → run key; เตรียมเสียงและบันทึกกลุ่ม |
| `pipeline/workspace_av.py` | Store + media ID → จำนวนหน้าต่างที่คำนวณเพิ่ม; บันทึกปากตามเวลาโดยรักษาการตรวจแก้ |
| `workspace/attribution.py` | Store + media ID → segments/results หรือข้อเสนอเชื่อมภาพเสียง |
| `workspace/appearance.py` | profile ID / ชุดสี → สีร่วมหลังผูก; metadata และ undo |
| `ui/cluster_dashboard.py` | ซับ/ผล/โปรไฟล์ → กราฟสมาชิกจริง ตารางคู่เสนอ และหน้าชุดสี |
| `ui/studio_layout.py` / `theme.py` / `icons.py` | วางสามหน้า เมนู ไอคอน และธีม; ไม่คำนวณ AI |
| `ui/project_navigation.py` / `project_dialog.py` | สร้าง/เปิด/จัดการ Home และฟอร์มเลือกโฟลเดอร์/สื่อ |
| `workspace/library.py` | JSON รายการ Home → เส้นทางและชื่อโปรเจกต์; ไม่เก็บ embeddings |
| `ui/subtitle_editor.py` | รับ SubtitleSegment → draft; คืน segment ที่ตรวจเวลาแล้วเมื่อกดบันทึก |
| `ui/waveform_worker.py` | วิดีโอ → waveform cache แบบ background; ไม่รัน AI |
| `ui/workspace_window.py` | การเลือก/สลับหน้า → Store/worker และ player สองบริบท; ไม่คำนวณ AI บน UI thread |
| `workspace_cli.py` / `workspace_app.py` | จุดเริ่มต้น Terminal / GUI ใช้แกนข้อมูลเดียวกัน |

คอมเมนต์ในโค้ดอธิบายเหตุผลของ ID, score, overlap, การยกเลิก, chunk และการรักษาการแก้มือ
ตัวอย่างทดสอบส่วนใหม่อยู่ใน `tests/test_multimodal.py`, `test_dashboard.py`, `test_active_speaker.py` และ `test_workspace_scan.py`
คำว่า `_` หน้าฟังก์ชันยังเป็นธรรมเนียมว่าเป็นรายละเอียดภายใน ไม่ใช่ข้อบังคับ private ของ Python

## งานที่ยังเหลือ

ต้องติดป้ายคำตอบจริงเพื่อวัดคุณภาพทั้งการแยกเสียง/จัดกลุ่ม/ระบุผู้พูด และปรับ threshold จาก validation set
การจัดกลุ่มปัจจุบันเป็น incremental ใช้ตัวแทนไม่เกิน 6 ชิ้นต่อกลุ่ม ไม่ใช่การ optimize clustering ทั้งเรื่องใหม่ทุกครั้ง
เสียง FX หนัก เสียงซ้อน คนพากย์หลายบท หน้าหัน/หน้าเล็ก และการตัดภาพเร็ว ยังทำให้ผิด/ไม่ตอบได้
ยังไม่มี ASR, การแยกผู้พูดที่ซ้อนเป็นคนละไฟล์เสียง, ชื่อจากฐานภายนอกอัตโนมัติ, gender/timbre classifier หรือ cloud sync
ดูผลทดสอบจริงและขอบเขตการยืนยันที่ [VERIFICATION_TH.md](VERIFICATION_TH.md)
MKV มีโหมด playback cache แล้ว แต่ยังต้องยืนยันด้วยการฟัง; ข้อจำกัดล่าสุดดู [KNOWN_ISSUES_TH.md](KNOWN_ISSUES_TH.md)
