# ปัญหาที่ทราบ — 17 ตุลาคม 2026

## ISSUE-AV-001 — หลักฐานปาก–เสียงยังไม่ใช่โมเดล lip-sync ที่ผ่านการวัด accuracy

สถานะ: มีคู่เสนอและ workflow ตรวจยืนยันแล้ว / ยังต้องวัดคุณภาพจากคำตอบมนุษย์

การเคลื่อนไหวปากเทียบกับ speech turn เป็น heuristic; การขยับใบหน้า มุมหัน บังปาก ภาพเล็ก
ภาพตัดเร็ว และอนิเมะที่หยุดภาพ/ปากไม่ตรงเสียง อาจให้ข้อเสนอผิดหรือไม่เสนอ
คะแนน 0–100 ไม่ใช่เปอร์เซ็นต์ความถูกต้อง; ชื่อที่เหมือนกันหรือสีเดียวกันไม่ได้เป็นหลักฐานจับคู่
ชื่อผู้พูดที่ระบุใน SRT/แก้ในซับช่วยเสนอคู่ได้เมื่อช่วงเสียงตรงชัดและชื่อกลุ่มภาพไม่กำกวม
แต่ซับอาจผิดหรือคลาดเวลา และข้อเสนอจากซับอย่างเดียวไม่พิสูจน์ว่าตัวละครนั้นขยับปาก
เสียงนอกจอและเสียงซ้อนอาจไม่มีคู่ภาพ ต้องตรวจเอง; FX/นักพากย์หลายบทอาจทำให้กลุ่มเสียงปนกัน
ควรแยกกลุ่มที่ผิดก่อนผูก เพราะการผูกใช้กับทั้งกลุ่มเสียงและทุกตอนที่อ้างกลุ่มนั้น

กราฟ Dashboard ใช้เส้น membership และความคล้ายเวกเตอร์เสียงโมเดลเดียวกัน ตั้งตำแหน่งด้วยแรงดึง–ผลัก
จึงไม่ใช่กราฟแกนสถิติหรือระยะ embedding ที่วัดได้; จำกัดตัวอย่าง 500 บทโดยไม่ลบข้อมูลจริง
ยังไม่มี benchmark ทั้งโปรเจกต์หลายสิบตอน และไม่รับรองว่าไม่เก็บภาพคนฟังเลย: ภาพคนฟังในช่วงมีเสียง
ยังใช้เป็นหลักฐานภาพได้ แต่ไม่ถูกถือว่าเป็นคนพูดจาก visibility เพียงอย่างเดียว

## ISSUE-MKV-001 — เสียงกระตุกเมื่อเปิด MKV

สถานะ: มีโหมดแก้ขัดข้องและแก้ seek ถี่แล้ว / ยังต้องยืนยันอาการด้วยการฟัง

17 ตุลาคม เพิ่ม cache สำหรับเล่น MKV เป็น MOV + stereo PCM 48 kHz และ copy video เมื่อ codec รองรับ
เปิด/ปิดได้จาก File → การเล่นวิดีโอ; ไม่เขียนทับต้นฉบับ ไม่ใช้ cache นี้ในการสแกน AI หรือส่งออกซับ
Slider ใน Editor/Manager จะ seek ครั้งเดียวเมื่อปล่อยเมาส์ ไม่ส่ง seek ทุกพิกเซล และอัปเดตเวลาปกติไม่ย้อนยิง seek
ไฟล์ cache เพิ่มพื้นที่ดิสก์ (PCM ~11.5 MB/นาที/แทร็ก บวกวิดีโอ) ต้องเตรียมครั้งแรกและใช้ซ้ำภายหลัง
มีการตรวจพื้นที่ว่าง/ความยาว/จำนวนแทร็ก/ต้นฉบับเปลี่ยน/ยกเลิก; cache ที่ไม่เสร็จไม่ถูกนำมาเล่น

ทดสอบ MKV Fate Strange Fake ตอน 02 ในเครื่อง ยาว 1,420.016 วินาที, H264 + AAC 44.1 kHz
ทั้งต้นฉบับและ cache เล่นช่วง 10–18 วินาทีแบบปิดเสียงได้ ไม่มี stall/error และ timestamp เสียงไม่ขาด
จึง **ยังทำซ้ำเสียงกระตุกที่ได้ยินไม่ได้ และยังกล่าวไม่ได้ว่าแก้หายทุกกรณี**
ทดสอบคลิปย่อย 12 วินาทีผ่านหน้าต่างจริง: สร้าง cache อัตโนมัติ สลับต้นฉบับ/preview แล้วเวลาและ draft ไม่หาย
หากยังสะดุด ต้องทราบช่วงเวลา อุปกรณ์เสียง และว่าเกิดตอนเล่นปกติหรือหลัง seek เพื่อตรวจ audio output ต่อ

## ISSUE-MAC-AX-001 — ตรวจ UI ผ่าน macOS Accessibility แล้วแอปปิด

สถานะ: มี guard ด้าน ownership และถอน selection ก่อนแทนแถวตาราง / ทดสอบ native ผ่าน

วันที่ 16 ตุลาคม พบ crash ขณะเครื่องมืออ่าน Accessibility hierarchy ของหน้าต่าง PyQt6
crash report ชี้ main thread ใน `libqcocoa.dylib` / `NSAccessibility` / `_AXXMIGCopyHierarchy`
ตรวจพบการลบ accessibility ID ของตารางแม่จาก synthesized row/cell ที่ยืม ID นั้นมาใน Qt Cocoa
มี guard เฉพาะ process ของแอป ไม่เปลี่ยนไฟล์ Qt/ระบบ ไม่ปิด Accessibility และไม่ติดตั้ง dependency ใหม่
control ที่ไม่ใส่ guard crash ด้วย SIGSEGV; ใส่ guard ผ่าน synthetic table 30 รอบ และแอปจริงอีก 24 รอบ
ตัวแก้จำกัดรุ่นและตรวจ ABI ก่อนใช้; native test ปัจจุบันเป็น Qt 6.11.2 ไม่ใช่การรับรอง Qt ทุกเวอร์ชัน
รอบทดสอบ MKV ตารางสองแถวยังมีคำเตือน AX เรื่อง selected child ระหว่างอัปเดต แต่ไม่ crash; ยังไม่รับรอง screen reader ทุกเส้นทาง
17 ตุลาคมพบอีกเส้นทางจากการลดจำนวนแถวขณะแถว 9 ยังถูกเลือก: crash report สองรอบอยู่ใน
`QTableWidget::setRowCount` → `QAbstractItemModel::endRemoveRows` → `QAccessible::updateAccessibility`
การถอน selected/current index ก่อนลดแถวอย่างเดียวยังไม่พอ เพราะ Cocoa เคยลบ interface ของเซลล์จริง
แต่ `QAccessibleTable::childToId` ยังเก็บ ID เดิมไว้ ตัว guard จึงรักษาทั้ง placeholder และเซลล์จริงไว้ให้
ตาราง C++ เจ้าของ ID เป็นผู้ลบเอง และทุกหน้ายังถอน selection ก่อนแทนแถวเป็นการป้องกันอีกชั้น
รายละเอียด ข้อกำหนด clang บน Mac และเกณฑ์ถอด workaround อยู่ใน [MAC_ACCESSIBILITY_FIX](MAC_ACCESSIBILITY_FIX.md)
